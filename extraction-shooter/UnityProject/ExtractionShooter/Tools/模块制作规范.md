# 模块制作规范

## 交付结构

- 每个模块交付 `World.prefab`、`HUD.prefab`、`ModuleDefinition.asset`、`PerspectiveProfile.asset`。
- `World` 只放地面、立面、装饰、视觉组件、锚点；`HUD` 只放屏幕界面。
- 经营、背包、存档、人物控制、场景服务放在场景接入脚本，不放入这两套预制体。
- 餐厅样例：`Assets/Modules/Restaurant/`；接入脚本：`RestaurantModuleAdapter`。

## 美术 / 地编

- 原点为模块中心。根节点缩放保持 `(1,1,1)`；尺寸通过视觉子节点调整。
- `GroundFrame` 局部 X 为地面左右，Y 为地面纵深，-Z 为离地高度。当前餐厅保留旧 XY 玩法平面；新 XZ 场景可整体旋转模块 X 轴 +90°，不能只旋转地面。
- 地面提供无相机透视的平铺纹理或正俯视地块。墙、栏杆、楼梯、家具独立出图。已有俯视角家具可保留；不要把包含墙和家具的整张效果图当作地面再次倾斜。
- 当前餐厅背景按纹理区域拆出地面、后墙、前栏，属于旧素材适配，不是未来素材交付标准。侧栏、楼梯的精确拆分需要独立源图。
- 家具以脚底/接地点为轴心；逻辑锚点放在所属家具组下面。移动 `TableSet`，桌椅及其锚点一起移动。
- 地面挂 `PlanarSprite` 并勾选 `ground`；地垫 `orderOffset=10`。立面不勾选 `ground`，依据统一镜头角度朝向并按脚底纵深排序。
- 物理根节点、碰撞体和移动脚本不得挂 `PlanarSprite`，不得随相机倾斜或缩放。
- 手绘图片使用透明背景、Bilinear 过滤；尺寸单位统一按 100 PPU 导入。视觉实际宽度以 prefab 为准。不要改原图尺寸后忽略 Sprite 切片复核。
- HUD 参考画布 1920×1080，Screen Space Overlay；四角控件锚定四角，队列锚定顶部中央，背包锚定底部中央。图片不得阻挡空白区域输入；按钮才接收点击。
- 先在 16:9 对齐 UI 参考，再检查 4:3 和超宽屏不越界、不遮挡主要操作区域。未实现控件只展示，不随意绑定其他功能。

## 程序

- `ModuleDefinition` 配对 World/HUD；选中配置执行 `Tools > Modules > Install Selected Definition` 创建成对实例。
- `ModuleWorld.anchors` 使用稳定、唯一 ID；必需 ID 写入 `requiredAnchorIds`。接入通过 `GetAnchor(id)`，不靠物体名称搜索。
- `ModuleHUD` 的按钮、文本、图片、容器分别用唯一 ID 注册；接入用 `GetAction/GetText/GetImage/GetRegion`，不得向通用类增加餐厅字段。
- 接入脚本绑定业务事件并在销毁时解绑。通过 `ModulePair.SetOpen` 管理 HUD 和镜头请求；离开、禁用、销毁必须释放请求、恢复玩家与旧 UI。
- `ModuleAnchorBindings` 连接旧逻辑目标和新锚点，运行开始时应用位置，不更改目标缩放、旋转、所属设施。移动已运行的玩法区域需由对应业务明确处理，不支持运行中随意拖动地编根节点。
- `ModulePresentationScope` 临时隐藏旧界面、暂停冲突的显示组件并恢复原状态；不要关闭仍需运转的经营脚本。多个模块的开关由业务入口串行管理，不并发叠开。
- `ModuleLegacyPopup` 临时承载旧界面并恢复原层级；它是过渡接入，不是新菜单设计。
- 跨世界/UI 的飞行动画使用各端点所属 Canvas 换算屏幕坐标，不能把 Overlay 的像素坐标当世界坐标。`ModuleScreenFlight` 只负责显示；业务宿主持有流程，关闭界面不撤销已扣食材的订单。
- `PlanarPerspectiveProfile` 控制倾角、FOV、距离、拖拽半径、速度及优先级。角度从地面法线算起，不是从地面算起。
- 鼠标输入统一经过 `CameraInputRouter`。拖拽使用两条鼠标射线与同一地面相交，不使用正交像素比例近似。
- 镜头投影、位置、近裁剪面由 `CameraDirector` 写入。透视近裁剪面必须为正，退出后恢复原正交值。
- 餐厅目前仍有 ProPixelizer 角色材质，保留原渲染器并暂停 CameraSnapSRP；不能只切到无像素处理的渲染器，否则角色显示异常。后续手绘模块可使用 ModuleRenderer，需配置相应渲染器索引并检查材质。
- 选中场景模块执行 `Tools > Modules > Validate Selected Pair`。缺失脚本、锚点、HUD 引用或重复 ID 必须先修复。

## 餐厅本次范围

- 地图按参考配置两排三列桌椅、两个灶台、两个摆菜台；外观数量不自动改变旧版的经营容量、解锁、价格或存档。
- 现有座位仍保留原餐桌的解锁归属；额外展示桌椅没有擅自增加经营席位。
- 新出口接原退出流程；装修接原装修面板；菜谱打开原经营界面。管理按钮暂不接业务。
- 队列沿用原 `DishQueueSlot` 对象和数据引用，是场景接入覆盖，不是纯 HUD prefab 自带经营能力。金币、进度读取旧系统；消息板、第二条信息栏、四格背包外框暂为展示，不伪造新业务。
- `IQueueIngredientPresentation` 是餐厅的可选显示接口；未接入模块时继续使用旧飞行方式。接入只替换飞行显示，保留扣除、队列、烹饪及原配置的等待时长。

## 局内战斗接入

- `Layer1/Layer2/Layer3` 共用 `Assets/Modules/Combat/DungeonPerspective.asset`，使用现有 XZ 玩法平面。地面平铺在 XZ，不能把整张带透视效果图再次当作地面倾斜。
- 站立精灵使用“物理/AI 根节点 → VisualRoot → Sprite”结构。`VisualRoot` 挂 `CameraFacingVisual`，使用 `EveryLateUpdate`；朝向翻转、动画放在 Sprite 子节点。脚底轴心不能偏离逻辑接地点。
- 实体 3D 地形、建筑、碰撞体不挂面向相机组件；地面贴花也不作为站立精灵处理。素材内部画出的俯视角须由美术统一，镜头不能补出缺失的顶部。
- 战斗使用 `DungeonPerspectiveProfile`，餐厅使用 `PlanarPerspectiveProfile`；共用镜头仲裁与输出，不把战斗鼠标前瞻和餐厅拖拽合并成一套操作。
- 战斗瞄准通过 `TopDownController.TryResolveAimPoint`；配置 Enemy 和 Floor 层，不能用屏幕坐标直接作为世界坐标。
- 叠加相机通过 `CameraStackPresentation` 注册给 `CameraDirector` 同步投影；其他脚本不能自行写入镜头参数。
- 后续新增怪物/植被按上述视觉层级制作；无需修改镜头框架。检查方式见 `局内战斗透视验收.md`。
