技能配置表 · 配表说明（策划版）

本文档面向策划同学：说明 Assets/CSV/技能配置表.csv 每一列怎么填、buff效果字符串怎么写、各数字在程序里如何生效。不要求会写代码，但需要与程序、关卡配置对齐 ID 与索引（例如关卡 statsId、地图绑定列表下标）。

说明：玩家场景状态由 PlayerStateManager 管理，与技能数值无关。技能数值由 ExcelConfigReader 读表，由 SkillTreeInitializer 解析 buff 并写入 WeaponStatsManager / PetManager 等。

数据怎么进游戏

  1. 运行时 ExcelConfigReader 读取 CSV，生成技能列表（含 buff 字符串、每级消耗等）。
  2. 技能树界面用这些数据生成节点、连线、升级消耗；玩家升级时调用 ApplySkillEffects。
  3. buff效果列被拆成若干段，按类型改武器、商店、地图密度、关卡刷怪/道具参数等。
  4. 很多属性先读初始属性表（工程里另一份 CSV，挂在 ExcelConfigReader.initialStatsCSV）作为基准，再按公式乘上技能等级。调平衡时要两份表一起看。

配表规则与常见错误

  • 编码：文件需为 UTF-8，否则中文可能乱码。
  • 第一行：必须是表头；数据从第二行开始；空行会被跳过。
  • 列分隔：英文逗号 ,。若某一格内容里必须出现逗号，整格用英文双引号包起来（解析器支持引号内逗号）。
  • 小数点：用英文点 .（如 0.05），不要用中文句号。
  • 列数：每一行必须能解析出至少 10 列，否则整行丢弃。少写了一个逗号就会导致后面列错位或行无效。
  • 技能 ID：唯一；前置里引用的 ID 必须能在表里找到对应行。
常见坑：在「buff效果」里手写嵌套括号时，括号必须成对；(49,(...)) 中间是英文逗号。等级消耗里多级用 | 分隔，段数应等于最大等级（或按程序约定），否则升级按钮可能对不齐资源消耗。

表头与列结构（共 10 列）

列序 表头 策划填写说明
0 技能ID 整数，全局唯一。前置、程序引用都用它。
1 技能名称 界面显示名称。
2 前置技能ID 见下文 前置技能列。
3 坐标 x,y 两个数，英文逗号分隔。决定技能树节点在 UI 上的位置（乘上网格间距后布局）。
4 最大等级 整数。与「等级消耗」条数强相关。
5 是否稀有 0 普通，1 稀有（具体表现以 UI 为准）。
6 技能描述 给玩家看的说明文案；不参与数值计算，但应与 buff 实际效果一致，避免投诉。
7 buff效果 核心列，见 buff效果 详解。
8 等级消耗 见 等级消耗列。
9 图标路径 见 图标路径。

前置技能列

  • 格式：填写前置技能 ID。所有前置技能只需达到 1 级。
  • 多个前置：用英文分号 ; 分隔，例：16;18。
  • 只允许填写正整数技能 ID，不再支持 技能ID:等级 格式。
  • 不要写循环依赖；引用的技能 ID 必须在同一张表里有定义。

等级消耗列

格式：资源类型编号:数量，每一段对应从 1 级升下一级的一次消耗（具体对应关系以当前程序为准：一般为第 1 段 = 升到 2 级消耗，以此类推）。

  • 多段之间用竖线 | 连接，例：0:5|0:5|0:10。
  • 资源类型编号 = 程序里 ResourceType 枚举的整数值（从 0 开始），见文末 资源类型编号表。

图标路径

填 Resources 文件夹下可加载资源的路径（不含 Resources/ 前缀）。可以带或不带 .png，程序会处理。填错会回退到默认图标。

buff效果 · 语法总览

一整格是一个字符串，可以包含多条效果：先用英文分号 ; 拆开，再逐条解析。

程序对每一条会按顺序尝试匹配下面几类（命中一类后就不再对同一条做其他解析）：

类型典型形式用途简述
关卡五元组(49,(levelId,…))按「关卡参数 ID」改刷怪与道具相关倍率
地图密度(30,(索引,系数))改某张地图植物/怪物密度绑定
凋落物密度(31,(索引,系数))改某种敌人掉落物权重
普通属性(数字ID,数值)改武器、商店、饱食度、餐厅、宠物等成百上千条属性

若一条字符串同时像多种格式，以程序中的匹配顺序为准：先 49，再 30、31，最后才是普通二元组（见 SkillTreeInitializer.ApplySingleEffect）。

① 普通属性：(statID, value)

写法：(整数 statID, 数值 value)。value 可正可负；与当前技能等级 level如何组合，完全由 statID 决定（乘算、加算、开关等见 速查表）。

「每级 +5% 伤害」在表里怎么体现？
若 statID 对应公式为 初始 × (1 + value × level)，则 value 填 0.05 表示每级多 5% 相对初始的增量（不是把 5% 再乘一次等级两次方，具体以该 ID 公式为准）。
技能等级 level 指什么？
指该技能当前已解锁等级（升级回调里传入的 level）。多级技能升一级会重新应用效果。

示例：(5,0.05) 在 statID 5（主武器基础伤害）下为乘算类，配合等级放大总伤害。

② 地图密度：(30,(levelID, multiplier))

用于按技能等级提高某一张地图配置的密度倍率。

  • levelID：在程序里是 WeaponStatsManager.mapDensityBindings 列表的下标（从 0 起）。不是关卡 statsId 字符串。
  • multiplier：系数，配合技能等级：最终倍率 = 1 × (1 + multiplier × 技能等级)。
策划要对齐：表里第几个绑定对应哪张图、哪类植被/敌人，需要对照 Unity 里 WeaponStatsManager 的 mapDensityBindings 列表顺序。改顺序会导致旧技能配置「指错图」。

配置示例（摘自现网表）：(30,(0,0.1))、(30,(1,0.1)) 等多条可写在一个技能的 buff 里，用 ; 分隔。

③ 凋落物密度：(31,(resourceIndex, multiplier))

用于提高某种敌人掉落物在生成逻辑里的密度倍率（绑定在 enemtLootDensityBindings 列表上）。

  • 第一个数字是列表下标，且该位置绑定的资源类型不能为 None，否则不生效。
  • 公式与 30 类似：lootDensityMultiplier = 1 × (1 + multiplier × 技能等级)。

示例：(31,(20,0.4)) 表示第 20 号绑定在技能等级提升时放大掉落相关倍率（具体是哪种掉落需对照编辑器绑定表）。

④ 关卡五元组：(49,(levelId, countV, spawnV, waitV, propV))

这是最容易问「每个字母什么意思」的格式，下面按程序实际用途说明（与 WeaponStatsManager.LevelParamRateItem 一致）。

整体规则：在关卡条目上先打快照基准，再按技能等级做乘法：

最终某倍率 = 该条目的快照基准 × (1 + 对应系数 × 技能等级)

五个参数依次为：

参数程序字段策划理解（干什么用的）
countV monsterCountRate 影响怪物数量上限相关倍率。消费端：MonsterSpawner 用 GetMonsterCountRate(statsId)，把配置里的 maxCount 乘上该倍率得到有效上限。
spawnV
(spawnIntervalV)		 monsterRapidSpawnIntervalRate 影响快速刷怪间隔倍率。消费端：MonsterSpawner 里 config.rapidSpawnInterval × rate。倍率变大 → 间隔变长 → 刷得变慢（若希望技能让刷怪更快，需要程序里用倒数逻辑或填负向设计，当前以乘法为准，填表前务必与程序确认期望）。
waitV monsterWaitTimeRate 影响数量减少后的等待时间（waitTimeAfterDecrease）倍率。同样由 MonsterSpawner 读取：配置值 × rate。
propV propProbabilityRate 影响关卡道具生成概率倍率。消费端：PropSpawnerManager 用 GetPropProbabilityRate(statsId)，与场景里配置的「抽取多少比例 PropSpawner 参与生成」相乘，再 Clamp01。倍率 > 1 时更容易轮到更多道具生成器工作（在不超过 100% 的前提下）。简单说：prop = 场景里可拾取物/道具点相关的概率权重，不是怪物数量。

其中 levelId 是字符串，必须与 WeaponStatsManager.levelParamRateItems 里某一项的 id 完全一致（通常与关卡 prefab / MonsterSpawner、PropSpawnerManager 上填的 statsId 对齐）。找不到 id 时程序会打警告且该条 buff 不生效。

书写示例：

(49,(forest_01, 0.1, 0, 0, 0.05))

含义示例：对 id 为 forest_01 的关卡参数条目，按技能等级放大怪物数量相关倍率一点，并略提高道具生成概率；其余两个系数为 0 表示不改间隔与等待。

为什么要单独讲 propV？

因为名字缩写不明显：prop ≈ Prop（关卡里随机生成的道具/拾取物），不是「属性点」也不是「怪物 prop」。和刷怪三条（数量、间隔、等待）并列，专门走 PropSpawnerManager 那条线。

多条效果组合

用分号连接即可，例如同时加背包格与商店格：

(21,2);(23,2)

策划协作提示

  • 改地图绑定顺序、关卡 statsId 列表前，先全局搜技能表里用到的 (30, (31, (49,(，避免旧数据失效。
  • 新技能上线前：在表里核对 buff 与描述、消耗与稀有度是否一致。
  • 对 (49,...) 中与「快慢」相关的系数（尤其 spawnV），建议拉程序一起看一次期望方向（当前实现是乘在配置间隔上）。
